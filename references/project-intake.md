# 项目接入规则

## 受理范围

仅在用户明确回复“确认生成，已获访问授权”后，接受以下项目来源：

- 远程 Git：无嵌入凭据的 `https://` Git 地址；SSH 地址仅在用户额外明确要求时使用。
- 本地目录：用户明确提供的绝对项目目录。

确认前不得探测远端、克隆、列目录、规范化路径或读取文件；确认卡和最终输出都不得回显地址、路径、仓库名、目录名、域名或账号。

## 远程 Git 接入

1. 拒绝 `file://`、`git://`、`ext::`、含 `@` 凭据、内网地址或其他非 HTTPS 协议；不要回显被拒绝的值。
2. 仅在权限为 `0700` 的随机临时目录中浅克隆：深度为 1、单分支、无标签、禁用子模块、禁用 LFS 下载、禁用凭据交互和钩子。
3. 不读取 `.git`、提交历史、远程地址、作者、分支列表、议题、PR、Wiki 或发布信息；这些信息不属于 E1 或 E2。
4. 无凭据访问失败或项目不可读时，只返回匿名缺口，并建议用户提供已检出的本地目录；不得索取 Token、密码或账号登录。
5. 无论成功、失败或中断，均清理本轮创建的精确临时目录。

## 本地目录接入

1. 确认后才规范化目录根。拒绝 `/`、用户主目录、工作区根、无法规范化或不存在的目录。
2. 只读取规范化根目录内的文本源码和测试源码；不跟随任何符号链接，跳过嵌套 `.git`。
3. 跳过 `.env*`、密钥/证书/凭据、部署与基础设施配置、CI 配置、依赖缓存、构建产物、二进制/压缩包和数据导出文件。
4. 禁止执行项目脚本、安装依赖、启动服务、构建、格式化或运行测试。测试源码可作为 E2；运行结果只能由用户提供并按 E3 处理。
5. 单体仓库有多个独立模块且用户未指定时，先用匿名问题请求确认模块；不得混合不同模块的证据。

## 取证与交付

- 远程或本地代码都只能形成 E2，不能证明候选人贡献。每条公开成果仍需用户明确确认 E1；含数字时还需 E3。
- 每个项目至少建立五个匿名 E2 证据点：入口、核心流程、数据模型、异常或权限边界、测试或运行验证。
- 原始 URL、路径、类名、文件名、代码片段和来源元数据只用于当前轮定位，不进入公开版、证据账本参数、错误信息或待确认项。
- 项目来源账本只记录匿名项目编号、来源类型和安全状态；不得记录 URL、路径、仓库名、目录名、账号或提交信息。
