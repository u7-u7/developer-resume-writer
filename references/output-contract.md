# 项目经历输出格式

## 默认 Markdown

```markdown
## <项目名称>

**项目简介**：<用 80–150 字说明：服务对象/场景 + 核心功能闭环 + 解决问题 + 技术机制>

**技术栈**：`技术 A`、`技术 B`、`技术 C`

### 项目产出

- **能力点标题**｜<做法>，<关键技术或机制>，<支撑的业务能力或规避的风险>
```

项目简介先回答“项目是什么、核心功能是什么”，项目产出再回答“做出了什么”。项目简介必须包含服务对象/场景、核心功能闭环、解决问题和技术机制。每条亮点都必须能回扣项目简介中的某项功能，内部包含“小标题 + 动作 + 技术方案 + 产出”，但用自然完整的一句话表达，不出现“动作：”“方案：”“产出：”标签；每条单独成行且不超过 200 字。无明确数据时，结果写“支持、实现、形成、覆盖”等功能性表述，不推断业务或性能收益。

## 现有简历优化

```markdown
## 优化建议

- **项目简介**｜问题：<缺少的核心功能或场景>；建议：<补充方向>
- **项目亮点**｜问题：<动作、方案或产出不完整>；建议：<改写方向>

## 优化后项目经历

<按默认 Markdown 格式改写的项目经历>
```

优化时不新增用户未提供的职责、数据或成果。若项目亮点没有可确认的结果，用“形成/支持/覆盖某项能力”替代夸大的效果词。

## CodeCV（可选）

用户明确要求 CodeCV 时，可将同一段内容放进 `项目经历` 区块，并使用模板 https://www.codecvcv.com/jianlimoban/15simple_versatile。建议主色 `#2F5CC4`、字号 `17`、行距 `15`、上下边距 `22`。
